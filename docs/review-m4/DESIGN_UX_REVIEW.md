# Map design and accessibility review

Family keeps Cards/List/Tree controls; a separate Map action opens `/family/map`. Profiles link to Map with memberId; Map groups expose existing profiles and member/address edit. Existing theme/language preferences persist unchanged. New VI/EN copy covers all five Backend statuses, queue feedback, numeric labels, saved/unsaved source, conflicts and provider failure. Full location names wrap and remain in the accessible list.

Mobile layout: native Family header/safe areas; actual compact stats; accent-insensitive search and All/Located/Unlocated segments; native map when configured; selected group details; virtualized groups and unlocated members. Selected group member rows also virtualize rather than embedding an unbounded list. No result slicing/truncation. Search matches full name/address/display name; a matching group intentionally includes its full membership, labelled as members in matching groups. Counts distinguish groups from people.

Missing key, Expo Go/web or missing native registration displays an honest unavailable explanation and full list/numeric alternative. It does not show a fake background. Provider errors/timeouts remain visible; Reload tiles recreates only the native surface. Attribution/logo stay present. Tap does not save. The editor scrolls with keyboard and keeps Cancel/Confirm reachable; Back cancels. Existing48px buttons/fields, semantic theme colors and AppText scaling are reused. Marker accessibility labels describe group name/count; selected/pending points differ in label and border/color.

Data refresh runs only on focused/foreground screen, at15/30/60 seconds capped to six attempts while PENDING, and stops on error/no pending. Foreground/manual refresh restarts the bounded budget. Explicit geocoding retry is serialized; queued counts never imply lookup success. Changing filters does not recenter polling/camera. Selection/search survive a profile pushed above Map while the route remains mounted.

Reduced-motion preference makes camera duration0 and modals do not animate. Shared M2 contrast audit remains required. Full TalkBack speech/focus traversal, external keyboard/modal focus, physical pinch/FPS and iOS/VoiceOver cannot be certified by source or adapters. Native viewport/font/language results are enumerated in NATIVE_SMOKE_RESULTS.md; unperformed checks stay NOT TESTED.

Observed Android evidence includes actual dark/light VIETMAP tiles and VI/EN controls,112-member full search,360dp/font130% and800dp layouts, real keyboard entry, Back/cancel, explicit save, profile return preserving selection, graph Fit/pan, offline recovery and localized expiry. Final camera controls use explicit wrapping flex bases so labels and48px targets fit compact/font-scaled layouts without excessive stretched row spacing. Test-only synthetic data is not a production fallback. Rapid mounted development-client configuration changes caused a root/linking warning; cold-start viewport checks pass, but this behavior remains an explicit open risk.
